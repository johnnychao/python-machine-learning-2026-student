### 1. 本章學習路線

在機器學習的開發流程中，資料前處理（Data Preprocessing）並非只是「清理資料」那麼簡單，它實際上是決定模型性能上限的實務支柱。業界有一句不變的真理：「垃圾進，垃圾出（Garbage In, Garbage Out, GIGO）」。即便你使用的是最先進的深度學習架構，如果餵給模型的是充滿缺失、刻度不一或邏輯錯誤的「垃圾」資料，預測結果也將毫無參考價值。

**本章學習路線**本章是連接「原始資料」與「高效模型」的橋樑。在實務中，資料前處理通常佔據資料科學家 80% 的工作時間。掌握本章，你才能確保模型在處理現實世界（Real-world）資料時，具備穩定性與泛化能力。

**學習目標**

**缺失值處理**：掌握刪除與填補（Imputation）的決策邏輯，並理解 Pipeline 整合優勢。

**類別資料轉換**：正確區分有序與名目資料，避開虛擬變數陷阱，並學會專業級的特徵轉換。

**特徵縮放**：理解標準化與正規化對演算法收斂的影響，並辨識無需縮放的特徵場景。

**防範資料外洩**：建立 `fit` 與 `transform` 的正確雙分流架構，防止模型「未卜先知」。

**特徵篩選技術**：運用 L1 正規化與隨機森林最佳化模型複雜度，對抗維度災難。

**重要術語中英對照表**

| 英文術語 | 中文譯名 | 定義 / 用途 |
| --- | --- | --- |
| Missing Data | 缺失值 | 資料集中的空白處（如 NaN），通常由問卷留白或量測失敗引起。 |
| Imputation | 填補 | 以統計值（平均值、中位數）補齊缺失資料的方法。 |
| Categorical Data | 類別型資料 | 非數值型資料，細分為有序 (Ordinal) 與名目 (Nominal)。 |
| One-Hot Encoding | 獨熱編碼 | 將名目資料轉化為獨立 0/1 欄位的技術，避免數值大小誤導。 |
| Feature Scaling | 特徵縮放 | 統一特徵刻度的過程（如身高與月薪），確保模型公平競爭。 |
| Data Leakage | 資料外洩 | 測試集資訊不當滲透進訓練過程，導致評估虛高的嚴重錯誤。 |
| Regularization | 正規化 | 透過懲罰項防止模型過擬合，L1 能同時達成特徵篩選。 |

掌握這些基本功後，我們才能確保模型的穩定性，首先讓我們面對真實資料的第一道關卡：缺失值。

### 2. 缺失值處理：缺失值填補

真實世界的資料絕非完美。在資料蒐集過程中，可能因系統故障或問卷留白而產生 `NaN` (Not a Number)。忽略這些缺失值會導致多數演算法在進行底層矩陣運算時直接崩潰，因為 `NaN` 的運算結果依舊是 `NaN`。

**核心觀念：刪除還是填補？**想像資料集是一張「考卷」：

**直接刪除**：移除含缺失值的資料列或欄位。這在資料量極大時可行，但若資料珍貴，過度刪除會流失關鍵資訊。

**合理填補**：參考其他資料點，使用合適的統計值填補缺失值。

**平均值填補 (Mean Imputation)** 是最常見的「不得已妥協」，但它會壓縮資料的變異性。實務上，若資料分佈偏斜（如薪資），選擇 **中位數 (Median)** 更具代表性；若是類別型資料，則須使用 **眾數 (Most Frequent)**。

**程式碼流程導讀**

**檢查機制**：執行 `df.isnull().sum()` 快速盤點破洞位置。

**執行填補**：利用 `SimpleImputer(strategy='mean')` 進行填補。

**實作建議**：pandas 的 `fillna` 可直接填補缺失值；若要把填補納入 scikit-learn Pipeline，請使用實作 Transformer 介面的 `SimpleImputer`。

### 3. 類別資料編碼：當顏色與尺寸變成數字

電腦只懂數字，因此我們必須擔任「翻譯官」。但要注意，「有大小關係」與「純類別」的轉法完全不同。

**有序 (Ordinal) vs. 名目 (Nominal)**

**有序資料**：具有邏輯順序，如尺寸（XL > L > M）。

**名目資料**：類別平等，如顏色（紅、綠、藍）。

**核心觀念：為何不能直接編 1, 2, 3？**如果你將「紅、綠、藍」編為「1, 2, 3」，模型會誤以為「藍色(3)比紅色(1)大三倍」，導致權重更新完全混亂。此時必須使用 **獨熱編碼 (One-Hot Encoding)**。

**術語焦點：虛擬變數陷阱 (Dummy Variable Trap)**獨熱編碼後，若已知衣服「不是紅」且「不是綠」，則它必為「藍」。這三個欄位存在高度相關，會導致數學運算不穩定（多重共線性）。因此，實作時必須設定 `drop_first=True` (或 `drop='first'`)，主動刪除一個欄位。

**程式碼流程導讀**

**有序資料**：建立映射字典 `size_mapping = {'XL': 3, 'L': 2, 'M': 1}`，使用 `df['size'].map(size_mapping)` 轉換。

**逆向映射**：為了後續報表解讀，使用 `{v: k for k, v in size_mapping.items()}` 建立反向字典。

**名目資料 (專業實作)**：對於多特徵陣列，專業做法是使用 `ColumnTransformer` 搭配 `OneHotEncoder`，這能讓你選擇性地對特定欄位編碼，同時保留其他數值欄位。

**重點： 進階技巧：閾值編碼 (Threshold Encoding)**如果你無法確定有序資料間的精確數值差距（例如 L 比 M 大多少？），可以採用「閾值編碼」。例如將尺寸拆解為兩個 0/1 特徵：「是否大於 M」與「是否大於 L」，這能更穩健地補捉順序資訊。

### 4. 資料外洩防範：Transformer API 的鐵則

這是在資料前處理階段最容易導致專案失敗的原因：**資料外洩 (Data Leakage)**。

**核心觀念：考前偷看期末考卷**想像一場考試。如果你在老師計算平均值（劃重點）時，把「期末考卷（測試集）」也混進去一起算，這就是外洩。模型在訓練時不經意地「偷看」了未來測試資料的分佈資訊，導致開發時準確率 100%，上線後卻慘遭翻車。

**程式碼流程導讀：雙分流鐵則**

**先切分**：務必先執行 `train_test_split`。

**fit 只能給訓練集**：`scaler.fit(X_train)`。這步是在訓練集找「標準」（平均數、標準差）。

**transform 兩者都做**：用訓練集找出的標準，去轉換訓練集與測試集。

**學習提醒**：口訣是「標準只能從訓練集找」。

### 5. 特徵縮放：標準化與正規化

特徵如「月薪（萬元）」與「身高（公分）」，數值級距差異極大。若不縮放，梯度下降演算法會偏心於數值大的特徵，導致路徑曲折、難以收斂。

**常見方案**

**標準化 (Standardization)**：將資料轉為平均值 0、標準差 1。它能保留離群值 (Outliers) 資訊，是 SVM 與邏輯斯迴歸的首選。

**常態化 (Min-Max Normalization)**：將數值壓縮至 \[0, 1\]。常用於影像處理或對邊界有特殊要求的場景。

**縮放與樹模型：**決策樹 (Decision Trees) 與隨機森林 (Random Forests) 是極少數「尺度無關 (Scale Invariant)」的演算法**。它們是根據數值的大小順序做切分，而非計算歐幾里得距離。因此，如果你使用的是這些模型，可以跳過縮放步驟。

* * *

### 6. 特徵篩選技術：L1 正規化與隨機森林

我們以著名的 **UCI Wine 資料集** 為例：它包含 178 個樣本與 13 項化學特徵。當特徵過多而樣本相對不足時，會引發 **維度災難 (Curse of Dimensionality)**，模型會陷入死背資料的過擬合狀態。

**逐步移除特徵的實作**

**L1 的稀疏效果**：L1 的懲罰項幾何形狀是「菱形」。在最佳化過程中，菱形的尖角極易與座標軸相交，這會強制將不重要特徵的權重變為 0，直接達成篩選。實作請用 `LogisticRegression(penalty='l1', solver='liblinear')`。

**SBS 逐步後向選擇 (Sequential Backward Selection)**：SBS 每一步移除一個對驗證表現影響最小的特徵，直到剩下指定數量的特徵。

**重要提示**：**SBS 目前並非 Scikit-Learn 內建的功能**，它通常需要自定義類別來實作。

**隨機森林重要性**：透過 `.feature_importances_` 屬性，你可以直接看出誰才是關鍵特徵（如 Wine 資料集中的 Proline）。
